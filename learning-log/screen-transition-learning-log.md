# 画面遷移図作成 学習ログ

## 概要

今回は English Output Trainer の画面遷移図および画面フロー図を作成した。

前工程で作成した画面設計書を基に、各画面の関係性やユーザーの操作の流れを整理した。

---

## 画面遷移図と画面フロー図を分けた理由

当初は画面遷移図のみを作成する予定だったが、整理を進めるうちに画面遷移図と画面フロー図では目的が異なることを知った。

画面遷移図は、

- どの画面からどの画面へ遷移するか
- ログイン画面やエラー画面をどのように経由するか

を表現するものである。

一方、画面フロー図は、

- ユーザーがどの機能を選択できるか
- 学習機能がどのような流れで分岐するか

を表現するものである。

今回のアプリでは、

- 通常学習
- お気に入り学習
- 復習
- 難易度別学習
- 順番出題／ランダム出題

などの分岐が多かったため、画面遷移図だけではユーザーの操作の流れが分かりにくかった。

そのため、

- 画面遷移図
- 画面フロー図

の両方を作成することにした。

---

## Mermaid記法を採用した理由

画面遷移図および画面フロー図は Mermaid 記法で作成した。

理由は以下の通りである。

- Markdown 内に直接記述できる
- GitHub 上でそのまま図として表示できる
- Git による差分管理が容易
- draw.io や PowerPoint のような専用ツールが不要

特に GitHub 上でプレビューできる点は大きな利点であり、設計資料とソースコードを同じリポジトリ内で一元管理できる。

また、仕様変更時もテキストを修正するだけで済むため、図形を手作業で編集する方式と比較して保守性が高いと感じた。

---

## 画面設計書の重要性

今回、画面遷移図と画面フロー図の作成は比較的スムーズに進めることができた。

その理由は、事前に画面設計書を作成していたためである。

画面設計書には、

- 各画面の役割
- 遷移先
- ボタンの動作
- 表示項目

などが既に整理されていたため、それらを基に画面間の関係を図へ落とし込むだけで済んだ。

改めて、画面設計書は単なる画面仕様ではなく、その後の画面遷移図や実装作業の土台になる重要な資料であることを実感した。

---

## 所感

画面遷移図と画面フロー図を作成したことで、アプリ全体の構造を俯瞰して確認することができた。

また、作業中には学習範囲選択画面が独立した画面として扱った方が自然であることに気付き、新たに画面を追加するなど設計の改善にも繋がった。

画面設計書から画面遷移図、画面フロー図へと段階的に設計を進めることで、アプリケーションの構造をより明確に整理できることを学んだ。
