# データ設計書・ER図・テーブル定義書 作成 学習ログ

## 概要

今回は English Output Trainer のデータ設計書、ER図、テーブル定義書を作成した。

ユーザー情報、問題情報、お気に入り情報、学習履歴を管理するために必要なデータ構造を整理し、テーブル間の関係や各テーブルの役割を明確化した。

---

## データ設計書について

企業によっては Excel や専用のデータモデリングツールを利用してデータ設計書を作成することもあるようだが、今回は個人開発であるため、画面設計書と同様に Markdown 形式で作成した。

データ設計書に必要な項目について調査したところ、本アプリケーションの規模であれば以下の内容で十分であると判断した。

- データベース概要
- エンティティ一覧
- エンティティ概要
- テーブル間のリレーション

企業や官公庁向けの大規模システムでは、これに加えて作成者情報、更新履歴、インデックス設計、ストアドプロシージャ、ビュー定義、サンプルデータなども管理することが多いようである。

今回はテーブル定義やER図を別ファイルとして管理したかったため、データ設計書ではエンティティ一覧とエンティティ概要を中心に整理した。

SQL の基礎知識があったこともあり、作成自体は比較的スムーズに進めることができた。

---

## ER図について

ER図は Mermaid 記法を利用して作成した。

当初は draw.io のような作図ツールも検討したが、Mermaid を利用することで Markdown 上で管理でき、修正や差分管理も容易であるため採用した。

ER図では、

- USER
- PROBLEM
- FAVORITE
- STUDY_HISTORY

の関係を定義した。

`USER ||--o{ FAVORITE` のような記法は初めて見たが、データ設計書のリレーション概要を先に整理していたため、それぞれが「1対多」の関係を表していることを理解すると、それほど難しくは感じなかった。

---

## テーブル定義書について

テーブル定義書は、一般的には Excel 形式で管理されているものをよく見かける。

しかし、Excel であっても Markdown であっても伝えている内容は同じであるため、今回はよく利用されている構成を Markdown の表形式で再現した。

各テーブルについて、

- カラム名
- データ型
- 主キー
- 外部キー
- NOT NULL 制約
- UNIQUE 制約
- 備考

を整理した。

また、お気に入りテーブルや学習履歴テーブルについては複合主キーを採用し、多対多の関係を適切に管理できるよう設計した。

---

## データ設計と画面設計の関係

データ関連の要件定義については、これまで SQL を学習していたこともあり、それほど苦労せずに進めることができた。

ただし、これは単に SQL の知識があったからではなく、その前段階である画面設計書や画面遷移図の作成を通じて、「どの機能を実装するのか」「どのような導線で利用するのか」を整理していたことが大きかったと感じている。

実際に画面設計が固まっていたため、

- お気に入り機能が必要
- 学習履歴を保存する必要がある
- 復習機能のために評価結果と学習日時を保持する必要がある

といった要件を自然にデータ構造へ落とし込むことができた。

改めて、データ設計は単独で行うものではなく、画面設計や機能設計の延長線上にある作業であることを実感した。
