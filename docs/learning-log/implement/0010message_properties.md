# 学習ログ：メッセージプロパティによる画面文言の外部化

## 概要

ログイン画面および新規登録画面の文言をHTMLへ直接記述するのではなく、messages.propertiesへ切り出した。

これにより、画面表示用の文言とHTMLの構造を分離できるようになった。

---

## 実装内容

### メッセージプロパティファイルの作成

画面で使用する文言を管理するため、messages.propertiesを作成した。

```properties
signup.title=新規登録
signup.btn=ユーザー登録
login.btn=ログイン
userId=ユーザーID
password=パスワード
confirm.password=パスワード(確認)
login.link=ログインはこちら
```

---

### HTMLから文言を取得するよう変更

従来はHTMLへ直接文言を記述していた。

```html
<h2>新規登録</h2>
```

これを以下のように変更した。

```html
<h2 th:text="#{signup.title}">新規登録</h2>
```

また、ラベルやボタンについても同様にメッセージプロパティから取得するよう変更した。

```html
<label th:text="#{userId}">ユーザーID</label>

<input type="submit"
       th:value="#{signup.btn}">
```

---

## 発生した問題

実装直後、画面には

```text
??signup.title_ja??
??userId_ja??
??password_ja??
```

のような文字列が表示された。

当初はロケール設定の問題を疑ったが、原因は単純であった。

ファイル名を

```text
message.properties
```

としていたため、Spring Bootがメッセージファイルとして認識できなかった。

正しくは

```text
messages.properties
```

である。

ファイル名を修正したところ、正常に文言が表示されるようになった。

---

## 学んだこと

Spring Bootではメッセージファイル名に規約が存在する。

デフォルトでは以下のファイル名が読み込まれる。

```text
messages.properties
messages_ja.properties
messages_en.properties
```

そのため、ファイル名を誤るとHTML側の記述が正しくてもメッセージを取得できない。

また、

```html
#{signup.title}
```

のような記述は国際化そのものではなく、まずは画面文言を外部ファイルへ切り出して管理する仕組みであることも理解できた。

## 所感

今回の実装自体はそれほど難しいものではなかったが、ファイル名のスペルミスによって予想外の箇所で時間を使ってしまった。

一方で、画面文言をHTMLへ直接記述するのではなく、プロパティファイルで管理するメリットを理解できた。

現時点では日本語のみを使用しており、この実装がアプリケーションの機能面において必要不可欠というわけではない。しかし、Spring Bootがメッセージプロパティをどのように読み込み、Thymeleafからどのように参照するのかという挙動を確認するために導入した。

また、将来的に英語版や中国語版を作成する場合でも、HTMLを修正せずに対応できる構成となるため、早い段階で経験しておいて良かったと感じた。

さらに、画面文言が一箇所に集約されることで保守性も向上すると感じた。
